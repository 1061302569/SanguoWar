# 三国战棋（SanguoWar）— Cocos Creator 3.8.8 原型

一款仿《欧陆战争 3》的六边形回合制战棋，题材为 194 年群雄割据的三国。
目标平台：**微信小游戏**（当前工程已按竖屏 720×1280 适配）。

---

## 一、如何运行

1. 用 **Cocos Creator 3.8.8** 打开本工程根目录（含 `assets/` 与 `settings/` 的那一层）。
2. 首次打开时编辑器会自动导入 `assets/` 下资源（`library/` 会重建）。
3. 双击 `assets/scenes/Main.scene`，点击预览即可开始游戏。

> 场景本身只包含 `Canvas` + `Camera`。整套界面由脚本 `Boot.ts` → `GameController.ts`
> 在运行时纯代码构建，**不依赖任何预制体、美术图片或字体资源**，
> 因此工程开箱即可跑通，也便于你后续替换成正式美术。

如果没有场景，`Boot.ts` 也会在场景启动时兜底创建 Canvas 并挂载主控制器。

## 一·五、构建到微信小游戏

工程里已经预置好一份可直接使用的微信构建配置，**不需要手动填一堆选项**。

### 1. 打开构建面板

菜单「项目 → 构建发布」，`平台` 选 **微信小游戏**。
配置已保存在 `settings/v2/packages/builder.json`，会自动带出：

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| 初始场景 | `Main.scene` | 已锁定主场景 |
| 设计分辨率 | 720 × 1280，fitHeight | 竖屏手机 |
| 设备方向 | `portrait` | 生成 `game.json` 的竖屏配置 |
| debug | 关闭 | 发布构建 |
| Source Map | 关闭 | 减小包体 |
| MD5 Cache | 开启 | 便于 CDN / 热更新缓存 |
| 引擎模块 | 14 个 | 已裁掉 spine、3D、物理、视频等 |

### 2. 填 AppID

构建面板的 `appid` 目前是占位值 `wx0000000000000000`，
**必须换成你自己的小程序 AppID**（在微信公众平台注册后获得），否则微信开发者工具无法导入。

也可以直接改 `settings/v2/packages/builder.json` 里的 `appid` 字段。

### 3. 构建并使用微信开发者工具

1. 点「构建」，产物在 `build/wechatgame/`。
2. 打开**微信开发者工具**，「导入项目」选这个目录。
3. 模拟器里即可运行；真机预览需要 AppID 通过审核。

构建完成后，`extensions/sanguowar-build-check` 插件会自动校验产物，
在控制台打印方向、appid、包体大小等信息，并对超包体、方向错误等问题给出警告。

### 4. 如果 game.json 方向不对

正常情况下构建模板已经写好竖屏。万一手工改过模板，可以运行兜底脚本：

```bash
node tools/fix-wechat-game-json.mjs build/wechatgame
```

## 二、玩法说明

| 操作 | 说明 |
| --- | --- |
| 点击城池 / 版图色块 | 查看该城池详情（归属、兵力、人口、工事、**发展度**、月收、月粮、**月募兵**、守将、**本城君威加成**、守将忠诚、当前自动方针） |
| 拖动地图 | 平移视角；滚轮/双指可缩放 |
| **我方势力身份牌** | 左上角常驻：势力主色色块 + 「我方 曹操 · 3 城」；点它会选中己方前线城并把视野移过去，开局不用猜自己是哪个势力 |
| **看路网** | 全部通路开局就画好、不用点城池：橙红带箭头 = 能进攻，绿色 = 只能调兵，浅色 = 现在打不了；点城池只是把相关路加粗 |
| **内政自动化（推荐）** | 面板上排最左是一个**「自动」开关**（不是第五个内政按钮，也不是第二套内政键）。打开后结束回合统一结算时，系统给「还没自己登记指令」的城执行**你最后点过的那道指令**；关上就是逐城手动（默认关）。这座城将要执行的那道内政键会亮底金边 |
| **内政（单城微调）** | 面板上排四个键，每城每回合四选一：**治理**（240 金 +8 发展度，之后所有月产出都更高）、**屯田**（一次性粮草，喂月募兵）、**筑城**（金 + 粮换 1 点工事）、**征兵**（花金币 + 人口补兵；一次只补 60% 缺口、最多动 25% 国库）。**回合内只登记选择，点「结束回合」才统一执行**：再点同一道可取消，点另一道可改选，不扣资源也不改数值。手动登记的城优先执行，自动不会覆盖它；手动点哪一道，自动之后就重复哪一道，且会明确提示方针已改 |
| **进攻** | 点「进攻」后，相邻敌城会被高亮，再点击目标即可开战（**不占**内政行动点）。**一座城一回合只能出征一次**：打完必须等募兵、调兵或征兵补充；攻破城池时每名守将按 50% 概率被生擒，新占领的城本回合也要整编、不能再出征。面板在每个可攻目标后标注战前胜算档位（高 / 优 / 险 / 慎），按兵力、守将、工事、君主加成算出，仅供参考，实战仍有浮动 |
| **俘虏营** | 顶栏「俘虏」按钮（营里有人时亮金边）。每名俘虏二选一：**招降**（成功率 =(100 − 忠诚)/100 + 我方君威；**在位**君主不可招降，**失去所有城池后可招**）或**放归**（回原势力、忠诚 −25，下次被俘更好招）。攻城结束会点名抓到了谁 |
| **调兵** | 点「调兵」后，相邻己方城池高亮，把出发城的兵**填满目标城**（出发城留 100 守备，**不占**内政行动点）。目标城可以**超编到上限的 3 倍**（临时集结），超编部分每回合流失 35% —— 想集中兵力打一个点，就得接受这个代价 |
| **后方补给（自动）** | 结束回合时，**不接壤敌军的后方城会把余兵自动送往一线**（保留 40% 上限做守备）。不需要手动一城一城搬，`+补给 N` 会在结算提示里报出来。这条对 AI 同样生效 |
| **结束回合** | 统一结算内政（手动登记 + 自动补齐）→ 收金币 / 粮草 / 人口增长 + 月募兵（每势力有总量上限）→ 超编损耗 → 后方补给 → 所有 AI 势力行动，进入下个月。战报报的是**本月实收** |
| **新局** | 顶栏按钮：选剧本、选执掌势力，随时重开一局（会清空当前进度） |
| **路网 / 隐路** | 顶栏按钮：切换常驻路网的显示（默认开） |
| **声 / 静** | 顶栏右侧开关音效，设置会记住 |

战斗时有箭头飞向目标、格子震动、兵力飘字；攻下城池会有整格闪光与音效。
演出期间按钮会短暂禁用，避免连点。

### 推进为什么有节拍（四条不能省的规则）

这四条不是「加机制」，而是把「兵够却打不出去」和「十回合推平全图」两个极端
同时摁住的底线。每条都对应一次实测过的失败：

| 规则 | 不设它会发生什么 |
| --- | --- |
| **一座城一回合只能出征一次** | 同一座城反复出征，打一波立刻接着打第二波，「攻城 → 损兵 → 补兵」的节奏整段被跳过 |
| **新占领的城本回合不能再出征** | 打下 A 立刻从 A 打 B，一回合连锁推七八座城（实测 11 回合统一天下） |
| **后方余兵自动补给到一线** | 兵只能按人口摊在每座城里，35 城 3.6 万兵、单城平均一千，谁都打不动；手动调兵每次只能调一半，三跳之后只剩 12%，190 回合只推进 9 座城 |
| **临时集结（超编 3 倍，每回合流失 35%）** | 双方都满编，单城对单城恒为 1:1，**总兵力是 AI 的十几倍也凑不出单点优势**；而金币堆到几十万却一个兵也征不出来 |

配套的两条经济闸门：`reinforceTotalCap`（每势力每月募兵上限）让「城多」不等于
「兵多」，`goldPerTroop`（1.3 金/兵）让金币真的能换成兵 —— 否则要么钱没用，
要么钱等于无限兵。

**验证方式**：`tools/sim-pace.ts` 用固定种子跑 6 局，同时断言
「每局都能通关」（不能卡死）和「最快 ≥10 回合、最慢 ≤60 回合、金币 <5 万」（不能太快）。
当前实测 **6/6 通关、18~21 回合、通关时金币峰值 4213、僵持回合占比 0%**；
作为对照，调参前是「200 回合卡在 32/35 城、金币 132 万」与「11 回合速通」两个极端。

### 提示系统（为什么以前“点了没反应”）

早期所有失败路径都是**静默**的：进攻条件不满足就直接 `return`，玩家什么都看不到，
自然以为是卡了。现在每一条失败路径都有具体原因：

| 情况 | 现在的提示 |
| --- | --- |
| 目标与自己不相邻 | 「洛阳与襄平不接壤，无法进攻」 |
| 目标是友军 | 「同为友军，请用「调兵」」 |
| 出发地没兵 | 「洛阳没有可用兵力，请先征兵」 |
| 该城四周无敌军 | 「许昌四周没有敌军，暂时无法进攻」 |
| 演出进行中点击 | 「战斗演出进行中，请稍候…」 |
| 战斗结果 | 「⚔ 攻占 邺！驻军 3200，缴获 410 金」 |

**面板会主动告诉你能打谁**：

- 自己城池：显示「可攻：邺、南皮」「可调兵：许昌」，或「⚠ 四周无敌军」
- 敌方城池：显示「可从：洛阳、许昌 进攻」，或「（我方与他并不接壤）」

**地图上开局就常驻画好全部路网**，按 `borders` 原样画出城与城之间的通路，
**不需要点任何城池**：橙红色带箭头的是「我方城 → 敌/中立城」的**能进攻**前线，
绿色是我方内部**只能调兵**的补给线，浅色是**现在打不了**的其他势力通路。
箭头永远指向可以打过去的方向；可攻目标城还带一圈橙红靶环，能出兵的己方城右上角有橙红点，
不点城池也能数出「现在能打哪几座」。选中一座城只会把相关路加粗，**不会淡化其余路**。
地图左侧提示条上方有三色图例，顶栏「路网」按钮可临时隐藏这一层。详见「八·七」。

**结束回合后自动选中一座前线城池**（优先选能直接进攻的），
不会再出现「结束回合后面板空白、不知道下一步做什么」。

**开局一眼找到自己**（详见「八·八」）：横幅点名「你执掌 X · N/35 城」，
随后 toast 说明「左上角是你执掌的势力 · 带金环的城就是你的地盘」；
之后信息一直留在左上角常驻身份牌上，不会像 2 秒横幅那样消失。
地图上己方版图提亮一档、己方城池套一圈常驻金环，和身份牌的主色互相对照；
换剧本、换势力、重开、读档都会重新点名执掌势力。

进度会**自动存档**：每次进攻、每次结束回合、以及切到微信后台时都会保存，
下次进入游戏自动接着上次的局面继续。


胜负：占满全部 35 个城池即为**统一天下**；失去全部城池则**败亡**。
触发任一种结局都会弹出结算面板（剧本、执掌势力、用时、据点数），可直接
「再开一局」「换个剧本」或「继续看看」；读档进来时若已是终局，也会直接给结算入口。
平时想换剧本，点顶栏「新局」即可。

```
   ├─ data/
   │  ├─ Types.ts               # 类型定义
   │  ├─ Factions.ts            # 18 个势力（名称、配色、简介）
   │  ├─ Provinces.ts           # 35 座城池（真实经纬度 + 显式相邻关系）

settings/v2/packages/

├─ validate-wechat-build.mjs    # 检查构建配置是否合规
├─ validate-scene.mjs           # 场景结构静态校验
├─ fix-wechat-game-json.mjs     # 兜底修正 game.json 方向
├─ bundle-test.mjs              # 把 .ts 源码打包成可被 node 运行的单文件
├─ render_map_preview.py        # 用 Pillow 渲染地图预览 PNG

├─ tune-combat.mjs              # 战斗参数扫描（调平衡用）
└─ gen-meta.mjs                 # 批量生成 .meta（通常用不到）
```

## 五、数值与平衡

所有数值集中在 `core/Balance.ts`，几个关键项：

- `attrition` / `maxRounds`：每场战斗的强度与轮数。当前（0.85 / 3）下，
  **均势攻城胜率约 29%**，2 倍兵力对 3 级工事近乎必胜，符合「守方优势、但优势兵力能推平」的手感。
  判定里有一条不能省：守方掉到崩溃线时，**攻方自己也不能崩**
  （`atkLeft > atkStart × collapseRatio`）—— 否则同兵力硬拼时双方一起崩，
  却判攻方赢，城墙与工事全白造。
- `fortPerPoint`：每点工事的防御倍率（0.08）。
- `garrisonCapPerPop`（45/点）+ `garrisonCapMin`（900）：驻军上限按
  **「当前人口与初始人口的较大者」**算。人口会被反复攻城削掉（每次 −10%），
  若上限跟着人口一起崩，地图上的「走廊城」（北平→襄平这种唯一通路）就会变成死锁：
  上限只剩两三百，后方几万兵送不进来，最后一座城永远打不下来。
  人口仍然决定收入与募兵，所以打烂的城依然虚弱，只是不会卡死。
- **临时集结** `overCapFactor`（3 倍）/ `overCapLossRate`（0.35）：
  调兵与征兵都允许把城堆到上限的 3 倍，但超编的兵每回合流失 35%。
  这是「集中优势兵力突破瓶颈」的唯一手段 —— 驻军上限是硬顶时，玩家的总兵力
  是 AI 的十几倍，却因为兵只能按人口摊在每座城里，**永远凑不出单点优势**。
  自动补给只填到上限、不替玩家超编：要不要付这个代价，是玩家的决定。
- `reinforceTotalCap`（400）：每势力每月募兵总量上限。月募兵原本按城累加，
  34 座城每回合白送近 3000 兵，打掉多少立刻补回，「攻城 → 损兵 → 补兵」
  的节奏根本不存在，十来个回合就推平全图。加上限后**城多不等于兵多**，
  想更快补充只能花钱征兵 —— 金币这才真正有了用途（也顺手治好了后期金币堆到上百万）。
- `goldPerTroop`（1.3）/ `popPerTroop`（0.005）：征兵单价与人口消耗。
  这两个是「兵源」的总闸门：单价太低则金币等于无限兵，太高则有钱也征不出兵；
  人口消耗 0.02 时会把城抽干（25 人口的城只能征 1250 兵），而人口恢复极慢，
  等于一次征兵换来不可逆的伤害。
- `captureGarrisonRatio`：攻下城池后留多少兵力驻守（0.55）。**这个值不能太低**，
  否则新城刚打下来就会被 AI 反手夺回，战线永远推不动。
- `aiAttackRatio`（1.15）：**五五开**的战力比基准。战力比 = 攻方
  `兵力 × (1+将领攻击×0.05) × 君威` ÷ 守方
  `兵力 × (1+将领防御×0.05) × 君威 × (1+工事×0.08)`。玩家面板的「胜算」
  与 AI 的出兵决策共用 `winRateOf()` 这一条曲线，两边看的是同一场仗。
- **AI 决策参数（全部是公开难度设定，行为见「八·十一」）**：
  `aiGovernMax`（1）/ `aiGovernDevThreshold`（70）是 AI 每回合最多治理几座城、
  发展度低于多少才治理；`aiMinWinRate`（0.42）是出兵最低胜算，够不着先去集结、不硬撞；
  `aiBreakthroughRatio`（1.75）是集结要凑到的战力比（消耗战约需 1.7~2:1 才打得崩守军）；
  `aiMaxFronts`（2）/ `aiMaxAttacksPerFaction`（3）/ `aiMaxAttacksPerTarget`（2）
  分别限制机会目标数、每势力每回合总出兵路数、单座目标的夹击波次；
  `aiRecruitBudget`（700）是每势力每回合最多花多少金币急征；
  `aiPlayerTargetBias`（1.1）是 AI 对玩家城的目标权重（>1 表示更愿意冲玩家）。
  试过更激进的一档（每势力 5 路）：玩家开局被打回 6 座城、一局拖到 50 回合；
  收敛到 3 路后 6/6 通关稳定在 18~21 回合（`sim-ai.ts` 27/27 会盯住后期不再停摆）。
  改这一组数请重跑 `sim-ai.ts` / `sim-pace.ts` / `sim-game.ts`。
- **发展度**：`devPerPop` / `devCityBonus` 决定开局发展度，`devOutputFactor`（1.0）
  决定唯一的倍率 `devFactor = 1 + dev/100 × devOutputFactor`，金币 / 粮草 / 月募兵 / 屯田共用；
  `governGoldCost`（240）/ `governDevGain`（8）决定治理的回本节奏。
- **粮草与月募兵**：`foodPerPop`（1.6）是月产、`reinforcePerPop`（3.5）是月募兵基数、
  `foodPerAutoTroop`（0.45）是每名募兵的粮耗。三个数要一起调：月产 `pop×1.6`、
  募兵吃 `pop×1.575` 才能基本持平；早先 0.25 只吃掉四成产粮，200 回合攒到 24 万，
  「屯田」形同虚设（`sim-development.ts` 第 5 段会盯住「粮草不足就不募兵」）。
- **驻军粮饷** `foodPerTroopUpkeep`（0.015/兵·月）：每名驻军每月都吃粮，区别于
  `foodPerAutoTroop` 只算新募兵。养重兵有持续代价，后方少驻军、野战军集中到前线才有
  意义；缺粮时粮草扣到 0 为止，不按缺粮溃散兵力（避免缺粮→掉兵→更守不住的死亡螺旋）。
- **守将参战上限** `generalsPerCity`（5）：一座城攻防等级只取评级最高的 5 名守将计入，
  超出的守将仍在城上、守恒不变，只是不再把等级一层层叠上去。否则亡国降将全堆进同一座
  中立城，防御倍率叠成谁都打不动的硬黑洞（实测 8 将叠到 3.8 倍防御，200 回合推不下）。
- `aiSupplyFactor`（0.7，**公开难度设定**）：AI 月募兵效率是玩家的 70%，
  用来抵消「AI 不会屯田 / 筑城、人口不掉、驻军长期满编」的滚雪球。
  注意 AI **现在会征兵**（`aiRecruitBudget`），只是不做另外三道内政；
  改这个数请重跑 `sim-ai.ts` 与 `sim-game.ts`。
- `recruitFillRatio`（0.6）/ `recruitGoldShare`（0.25）：单次征兵只补六成缺口、
  最多动四分之一国库，避免一点「征兵」就国库清零、自动征兵只惠及一座城。
- **君主 / 忠诚 / 俘虏**：`captureGeneralChance`（0.5）是攻破城池时每名守将被生擒的概率；
  `releaseLoyaltyDrop`（25）是放归后降的忠诚、`persuadeFailLoyaltyGain`（10）是招降失败后升的忠诚；
  `recruitLoyalty`（60）是归降后对新主的初始忠诚；`loyaltyMin`（10）保证反复放归也不会变成 100% 白送；
  `fallenLoyaltyDrop`（30）是亡国时全势力降忠诚，让「亡国君主可招降」真正成立。
  成功率只有一个公式 `(100 − 忠诚)/100 + 我方君威`，且**在位君主恒为 0**，详见「八·十」。
- `Balance.ts` 里每个字段都必须有引用，`sim-development.ts` 有守卫逐个检查，
  防止再出现 `turnLimit` / `recruitMin` 这类从未接线的假参数。

改动后建议重跑 `tools/tune-combat.mjs` 观察胜率分布。

## 六、地图：真实地理

地图不再是抽象六边形网格，而是**按真实经纬度投影的中国版图**。

### 数据

`data/Provinces.ts` 里每座城都有真实经纬度，例如：

```ts
{ id: 'changan', name: '长安', lat: 34.27, lon: 108.94, ... }
{ id: 'jianye',  name: '建业', lat: 32.06, lon: 118.80, ... }
```

`core/Geo.ts` 用等距圆柱投影（经度按中纬度余弦收缩）把经纬度换算成屏幕坐标：

```
x = (lon - 99) * cos(31°) * 52
y = (43 - lat) * 52
```

### 相邻关系改成显式声明

这是本次改动最关键的一处：**相邻关系不再由网格几何推导，而是在数据里显式写 `borders`**。

原因很直接——真实城池的位置是稀疏、不规则的，塞进规整网格必然失真。
改成显式声明后，坐标可以完全忠于真实地理，同时相邻关系按史实（如襄阳—江陵沿汉水/长江、
寿春—建业隔江对峙）自由定义。

```ts
{ id: 'xiangyang', ..., borders: ['wan', 'jiangling', 'shouchun', 'changsha'] }
```

测试会校验四件事：**每座城都有邻居**、**相邻必须双向对称**、**没有自环**、**全图连通**。

### 地图画面

- **海陆分离**：先铺海洋底色，再填陆地多边形，渤海湾与山东半岛的形状能看出来
- **陆地底色**：统一米色底，不做按纬度切分的色带（色带会让地图看起来被切成几块，见下方「绘制要点」）
- **己方标识**：己方版图在势力色基础上再提亮一档，己方城池套一圈常驻金环（深色外圈 + 亮金内圈）；只增强己方、不淡化其余势力，金环属于城池标记而非贯穿地图的线（见八·八）
- **不画装饰线**：山脉 7 条、河流 5 条、州界粗线、35 个版图边界细线全部从绘制流程移除。
  它们和路网叠在一起会显得很乱；数据仍保留在 `MapRenderer.ts` 顶部，
  以后要做「可开关的地形层」可以直接恢复
- **湖泊**：洞庭湖、鄱阳湖、太湖（色块，不是线，保留）
- **路网**：地图上**唯一的线**，城池按 `borders` 连线的独立图层，全部 58 条常驻清晰显示，
  按「能进攻 / 只能调兵 / 现在打不了」分色，不点城池也能看（见八·七）

### 绘制要点（几个踩过的坑）

Cocos 的 `Graphics` **没有裁剪功能**，这决定了地形怎么画。以下是实际踩到的坑，
它们的共同症状都是「地图看起来被切成好几块」：

1. **不要用分区着色做地形带**。
   - 曾按纬度切成 12 条色带分别填充 → 横向 12 个色块；
   - 又试过高原用 6 条 alpha 渐变的竖直条带 → 从西到东 6 条竖直色块（更明显）。
   - 结论：Graphics 的半透明叠色只适合零星点缀，**绝不能拿来做大面积渐变**。
   - 现在陆地是**一次填充、单一颜色**，地形层次交给版图色块、湖泊、城池与路网；
     山脉与河流数据保留但不再绘制，避免和路网叠成一团乱线。

2. **描边不要描地图西边界**。陆地多边形含「左边界」，若整条轮廓都描边，
   左侧会出现一条贯穿上下的竖线，看起来就是分割线。现在只描海岸线。

3. **陆地多边形要补齐北部边界**。海岸线首点在 42.5°N 而地图上界是 43°N，
   闭合时若直接首尾相连，顶部 0.5° 会露海。必须补一段
   「左上角 → (海岸线首点经度, 上界)」的边。

4. **同一纬度可能有几段陆地**。辽东半岛与山东半岛在 lat 39~40 并存、
   雷州半岛与广西陆地在 lat 20~21 并存。填充时要按段处理，不能取「最左到最右」。

5. **东北和辽西要留够陆地**。海岸线起初收得太紧，导致**襄平、北平两座城落在海里**。

### 地图操作（试玩后发现并修掉的问题）

「模拟试玩」脚本 `tools/sim-play.ts` 用**真实屏幕坐标**去点每一座城，检查操作手感。
这条路子查出 4 个真实缺陷：

1. **预览图比例与游戏不一致（最隐蔽）**
   预览脚本里 `SCALE=78`，而 `core/Geo.ts` 里是 `52`。
   于是我按 78 算间距“全部通过”，实际游戏里城池只有 21px、手指点不中。
   → 现在预览脚本**从 `Geo.ts` 读取 SCALE**，不会再漂移。

2. **初始缩放太小，城池直径只有 21px**
   手机可点目标建议 ≥26px，21px 基本点不准。
   → 改为「填满高度」，缩放从 0.62 提升到 1.03，城池直径 **35px**。

3. **拖动边界计算错误**
   `clamp` 里算 `(屏幕宽 - 地图宽)/2`，当地图比屏幕宽时结果是**负数**，
   导致拖动范围反转、地图能拖出屏幕露出大片背景。
   → 改为严格规则：地图比屏幕大时边缘不能越界，比屏幕小时居中锁定。

4. **缩放下限设置错误**
   原按「填满宽度」设下限，但地图宽高比 0.93、竖屏 0.56，两者形状不同，
   填满宽度后地图高度只有 775px < 屏幕 1280px，**上下各留 250px 空白**。
   → 改为按「填满高度」设下限。

**额外补充的便利功能**：

- **双击城池**：放大并居中到该城（聚焦后城池 69px，非常舒适）
- **「全图」按钮**：一键回到全国视野，拖远后不会迷路
- **命中容错**：屏幕命中圈不小于 22px 半径，缩小后依然好点



几何和配色问题很隐蔽，所以有专门的检查：

```bash
node tools/check-map-geometry.mjs
```

验证项：多边形无自交、各纬度陆地形态正常、**所有城池在陆地内**、
海面点判为海、陆地关键点判为陆、**陆地覆盖画布边界（顶部不露海）**。

> 注意：这个脚本只校验**几何数据**，不校验渲染结果。
> 「分成好几块」这类纯视觉问题，是靠渲染 `tools/map-preview.png` 后
> 逐像素统计颜色分布才定位到的——当时发现陆地面积被 6 种近似色分散，
> 才确认是高原渐变条带造成的。

```bash
python tools/render_full_ui.py      # 画完整界面（地图+HUD）→ tools/ui-preview.png
```

两个脚本都与游戏内使用同一套投影、配色和填充逻辑（`SCALE` 直接从 `core/Geo.ts` 读取）。

### 点击与进攻失效（根因排查）

用户反馈「点城池没反应」「有反应也打不了」。写 `tools/sim-interaction.ts`
模拟真实触摸链路后，定位到**三个叠加的坐标系 bug**：

#### 1. 触摸坐标没转换（最致命）

```
EventTouch.getUILocation()  →  原点在屏幕左下角，范围 [0,720]×[0,1280]
MapCamera / mapRoot 本地坐标 →  原点在 Canvas 中心，范围 [-360,360]×[-640,640]
```

直接传会整体偏移半个屏幕。实测：**35 座城一座都点不中**。修法是所有需要
与地图几何比较的地方先过 `uiToCamera()`。

#### 2. 地图投影与节点原点不一致

`Geo.project()` 原本返回「左上角原点的正值坐标」，而节点本地坐标以中心为原点，
导致绘制和命中整体偏了半个地图。现在统一为**中心原点**：

```ts
x = (lon-99)*COS*SCALE - width/2
y = (43-lat)*SCALE       - height/2
```

`mapRoot` 也去掉了多余的 +200 边距（那会让原点再偏 100px）。

#### 3. 双击检测抢在攻击判定之前

进入攻击模式后快速点目标，会被误判为「双击同一座城 → 放大聚焦」，
玩家看到的就是「有反应但打不了」。现在**攻击/移动模式优先于双击**。

### 顺带修掉的手感问题

| 问题 | 原因 | 修法 |
| --- | --- | --- |
| 点击偶尔没反应 | 拖动阈值 12px 太严，手指抖动 3~8px 就把点击误判成拖动 | 放宽到 22px |
| 打完一下有 620ms 点不动 | 演出期间拦截所有点击 | 缩短到 420/300ms |
| 攻击模式下点自己的城，模式被静默重置 | `selectProvince` 无条件重置 mode | 保持模式并提示「请点击红色高亮的敌城」 |
| 进攻失败后不知道下一步 | 演出结束只选中目标城 | 没攻下则回到出发地，提示「兵力 X，可征兵后再攻」 |

### 缩放/拖动后的 UI 问题

「放大缩小再拖动，UI 出问题」。用 `tools/sim-zoom-drag.ts` 逐序列复现，
查出**两个独立缺陷**：

#### 1. 标签跟着地图一起放大

标签是 `mapRoot` 的子节点，会随地图缩放。放大到 2.2 倍时字号从 17px 涨到 **37px**，
相邻城池的标签糊成一片：

| 缩放 | 标签实际字号 | 评价 |
| --- | --- | --- |
| 1.03 | 17.4px | ok |
| 1.60 | 27.2px | ok |
| 2.20 | 37.4px | 字太大，互相挤压 |

**修法**（地图类 App 的标准做法）：给标签节点设 `1/zoom` 的缩放，
抵消父节点的放大，让**屏幕字号恒定在 17px**。

#### 2. `pickAt` 用节点旧值覆盖了相机状态

`pickAt` 里原本有 `syncFromNode()`，会用 `mapRoot.position` 覆盖相机位置。
但拖动时相机已过 `clamp` 修正，节点上的值可能还是上一帧的：

```
拖动 + clamp 后：  相机 (306, 77)
节点上的旧值：     (0, 0)
点击时 syncFromNode：相机被改回 (0,0)   ← 判定位置错了
```

**修法**：确立「相机是唯一真相源」，只做「相机 → 节点」单向写入，禁止反读。

### 坐标系统的三条铁律

这一轮反复踩坑，总结出必须遵守的约定：

1. **触摸坐标要转换**：`getUILocation()` 原点在左下角，相机原点在中心
2. **地图投影以中心为原点**：`Geo.project()` 与节点本地坐标保持一致
3. **相机是唯一真相源**：禁止从节点反读回相机

### UI 布局（试玩后重做）

`render_full_ui.py` 按真实的 Widget 坐标把整个画面画出来，问题就藏不住了：

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 省份面板盖住中原 | 右上角 360×420 浮窗压住洛阳/许昌/谯，正是开局最常看的区域 | 改成**底部抽屉**（720×240），横跨屏幕下方 |
| 面板文字压住按钮 | 7 行正文排到按钮上，文字被遮 | 按钮改用 Widget 固定在面板底部 |
| 顶栏文字挤成一团 | 「194年1月 第1回合」与「兵力 3073」几乎连在一起 | 左列移到 -330、右列 -70，各自限宽 |
| 「全图」按钮露在栏外 | 按钮 y=-52，而顶栏半高只有 48 | 收到栏内，改 y=±22 上下排列 |
| 战报与提示条重叠 | 战报 bottom:130 起，正好压住提示条 | 战报移到左上，提示条移到面板上方 |
| 地图下方露出 300px 海面 | 相机设了位置但没做边界修正 | 统一走 `MapCamera.resetToStartView()` |

**关键教训：坐标约定必须统一。** 反复出错的地方是「屏幕坐标以中心为原点」还是
「以左上角为原点」——`clamp()` 和 `isOnScreen()` 曾各用一种，导致地图偏了半个屏幕、
几乎所有城池被判为"不在屏幕内"。

现在几何逻辑全部收敛到 `core/MapCamera.ts`，游戏与测试**共用同一入口**
`resetToStartView()`，不会再出现两边算法不同步。

## 七、战斗演出与音效

### 演出时间轴

点击进攻后，`BattleShowcase` 按下面的节奏播放（数值**在此之前**已经结算完毕）：

```
0.00s  箭头从出发地飞向目标（带轻微抛物线）
0.28s  命中：目标格震动 + 双方损失飘字（红，向下）+ 打击/胜利/挫败音
0.55s  若攻下：整格闪光 + 驻军数字（绿，向上）+ 占领音
0.62s  演出结束，恢复面板按钮，刷新界面
```

演出期间面板按钮会禁用，避免连点造成状态错乱。

### 关键设计：动画只是表现，数值才是真相

`doAttack` 里是「**先 `state.attack()` 结算，再播动画**」。这样即使玩家切到后台、
动画被系统中断，战斗结果也已经写进状态里，不会出现「动画没播完、兵力算错了」的问题。

`tools/sim-showcase.ts` 专门验证这一点：同一随机种子下，
走演出流程与直接结算的战斗结果**逐字段一致**。

### 音效：运行时合成，零音频资源

项目里**没有任何音频文件**。`core/SfxSynth.ts` 用正弦波 + 噪声 + 包络实时合成 5 种音效：

| 音效 | 音色设计 | 时长 |
| --- | --- | --- |
| `hit` | 高频噪声 + 金属泛音（刀兵相接） | 0.16s |
| `capture` | 低鼓 + 上扬号角（攻城得手） | 0.42s |
| `fail` | 低频闷响（进攻受挫） | 0.24s |
| `click` | 极短双高频（界面点击） | 0.05s |
| `turn` | 钟磬三音叠加（回合更替） | 0.42s |

这么做的理由：

1. **包体不增加**——省掉几十 KB 到几百 KB 的音频文件，对 4MB 主包很值。
2. **可调**——音色参数全在代码里，改完刷新就生效，不用重新导资源。
3. **零版权风险**——完全合成，不涉及素材授权。

`audio` 引擎模块也因此**可以从构建里移除**（模块数 22 → 13）。
日后要换成真实音效素材，只需改 `AudioPlayer.getBuffer()` 从 `AudioClip` 取数据，
其余调用点不用动。

> 想调音色：改 `core/SfxSynth.ts` 里对应分支的参数，
> 然后跑 `node tools/bundle-test.mjs tools/logic-test.ts` 确认波形仍在合法范围。

## 八·六、回合结算与地图刷新（对手回合染色不刷新的坑）

**现象**：对手回合攻下我方城池，到了我方回合，城池归属在面板和战报里已经变了，
地图上的势力色却还是旧的；玩家自己进攻时不会出这个问题。

**根因**（三件事叠在一起）：

1. `GameState.endTurn()` 里的 `runAiPhase()` 会调用 `attack()`，直接改写
   `ProvinceState.owner` —— 状态层是唯一真相源，**数据本身没有错**。
2. 版图颜色只在 `MapRenderer.draw()` 里按 `p.owner` 重新填充；
   `GameController.update()` 每帧只画选中光晕（`drawGlow`），**不会重画底图**。
   也就是说颜色不会自己跟着数据变。
3. 原来 `GameState.onTurnEnd` 是个**从不触发的死钩子**，
   `GameController.onEndTurn()` 在 `state.endTurn()` 之后只做了存档、横幅、
   结算检查和选中前线，没有 `refreshAll()`；而 `doAttack()` 里有显式
   `refreshAll()`，所以只有对手回合漏刷新。

**修法：状态层发信号、UI 层统一订阅**，而不是让每个调用点自己记得刷新：

```ts
// GameState.endTurn() 末尾（经济、日期、回合号都结算完之后）
if (this.onTurnEnd) { this.onTurnEnd(report); }

// GameController.onLoad()（必须在 buildMap / buildHud 之后）
this.state.onTurnEnd = () => this.refreshAll();
```

`refreshAll()` 会重绘底图、同步命中引用、刷新城池标签兵力、HUD 与战报，
一次把「数据变了但画面没变」的表现全部补齐；`onDestroy()` 里解绑，
避免组件销毁后回调还指向已销毁节点。`state.reset()` 不清这个回调，
因此「新局 / 换剧本」之后依然生效。

**顺带补的体验**：`TurnReport` 增加 `lostCities`（AI 阶段前后对玩家据点做差集）。
失守时横幅仍是「失守 N 城」，toast 会直接点名（最多列 2 个，避免 560px 溢出），
否则光看地图不一定找得到哪块版图变了色。

**铁律**：以后任何会改 `owner` / `troops` 的新流程，要么走 `refreshAll()`，
要么在状态层发信号；不要在 `update()` 里按帧重画整张地图（35 个多边形，没必要），
更不要指望「下次点击会顺手刷新」。`tools/sim-turn-refresh.ts` 同时守卫
逻辑层回调与 UI 层接线，改动后请跑一遍第 14 条验证命令。

## 八·七、路网：让玩家一眼看出能打哪里

**现象**：地图上两块版图挨在一起，点了却提示「不接壤，无法进攻」；
反过来，真正能进攻的两座城之间又什么标记都没有，只能靠面板里的「可攻：XX」去猜。

**根因**：这是两套不同的「相邻」。

| | 数据来源 | 用途 |
| --- | --- | --- |
| 版图色块 | `buildTerritories()` 按经纬度算的 **Voronoi** | 势力范围、点击命中 |
| 通行/进攻 | `ProvinceDef.borders` **显式声明** | `isAdjacent()` / `canAttack()` / `attackTargets()` |

Voronoi 只看几何距离，而 `borders` 按真实地理接壤与史实用兵路线写死，两者并不一致。
以前地图上根本没有画线，只有进入进攻/调兵模式后才从出发城画几条虚线，
于是「看得见的相邻」和「打得通的相邻」完全对不上。

**修法**：新增一层常驻路网，**只用 `borders` 这一份数据**，绝不从版图多边形反推。

```ts
// core/Routes.ts：纯逻辑，不依赖 cc，可直接被 tools 测试
const routes = buildRoutes(provinces);              // 去重后的无向边
const kind = routeKind(ownerA, ownerB, playerFaction); // front / supply / other
const dir = routeAttackDirection(route, ownerA, ownerB, playerFaction); // 玩家城 -> 敌城
```

| 颜色 | 含义 | 判定 |
| --- | --- | --- |
| 橙红 + 箭头 | **能进攻** | 一端是玩家、另一端不是；箭头指向可打过去的方向 |
| 绿色 | **只能调兵** | 两端都是玩家 |
| 浅色细线 | **现在打不了** | 两端都不是玩家 |

橙红箭头表达的是**通路关系**（能不能连着打），不是当前兵力够不够：
出发城兵力为 0 时点「进攻」会提示先征兵，面板也会给出「⚠ 无兵力」。
让路色只随归属变化，就不会因为征兵、调兵而频繁闪烁。

**为什么所有路都要常驻**：初版把 49 条「其他通路」压成淡底纹，又在选中城池时
淡化其余路，玩家的实际感受是「不点城池几乎看不到路，点了才画出来」。
现在颜色 + 箭头本身就回答了「能不能进攻」，所以**全部 58 条路一律完整清晰显示**，
选中只加粗相关路、放大箭头，绝不淡化其余。图例也直接写成
「▲ 能进攻 / ● 只能调兵 / ● 现在打不了」。

视觉处理上的几个决定：

- **双层描边**（深色外描边 + 亮色内芯）：无论压在深色势力版图还是浅色中立版图上都看得清。
- **端点留白**：`trimSegment()` 按城池半径裁掉两端，驿道从圆点外缘起笔，不压住城池圆点和文字标签；两端各点一个「路口」小圆，明确接到哪两座城。
- **两遍绘制、但不淡化**：先画非聚焦路、再画聚焦路，保证选中的路压在最上层；两遍都按完整 alpha 与线宽画，聚焦路只是更粗、箭头更大。
- **常驻可攻标记**：`drawAttackMarks()` 遍历全部前线，给可攻目标城画橙红靶环、给能出兵的己方城右上角点一个橙红实心点。不点任何城池也能数出「现在能打哪几座、从哪几座出兵」。
- **缩放补偿**：`setRouteScale()` 让线宽按 `mapRoot` 缩放取倒数，放大到 2.2 倍时驿道不会粗得盖住城池（与标签的反向缩放同一套机制）。
- **独立 `Routes` 图层**：层级为 `Terrain < Routes < Glow < Highlight < 文字标签`。重画路网不必重绘 35 个版图多边形；`MapRenderer.draw()` 在归属变化时一起重画，所以对手回合攻下城池后，「绿路变橙红前线、箭头翻转」也会跟着刷新。
- 顶栏「路网 / 隐路」可临时隐藏；提示条上方有三色图例。
- **底图只有路网一层线**：山脉 7 条、河流 5 条、州界粗线、35 个版图边界细线
  都已从 `MapRenderer.draw()` 移除 —— 它们曾和 58 条路叠在一起显得很乱。
  数据常量保留在文件顶部，以后想做「可开关的地形层」可以直接恢复；
  选中光晕与目标描边属于交互态，只在需要时出现，不算常驻线。

**数据层修正（用户反馈「襄阳隔着江陵能打长沙」）**：这不只是画面问题，
`Provinces.ts` 的 `borders` 里确实写了「襄阳 ↔ 长沙」「姑臧 ↔ 天水」两条越城直达。
已双向删除，改走 `襄阳 → 江陵 → 长沙`、`姑臧 → 金城 → 天水`，路数由 60 变 58。
`tools/sim-routes.ts` 用点到线段的距离守住「任何路都不能从第三座城身上穿过去」
（阈值 = 城池圆点半径 + 20px，避免误伤城池密集区里正常的三角邻接），
并把这两个案例锁成具体断言；`logic-test` 同时确认删边后全图仍连通、邻接仍对称。

**替换掉的旧行为**：`drawHighlights()` 里从出发地画到每个目标的虚线已删除 —— 路网已经是实线 + 箭头，再叠一层虚线只会显脏。现在高亮层只画目标版图描边、城池靶环和出发城起兵环。

**铁律**：

1. 以后新增城池或改通行关系，一律改 `Provinces.ts` 的 `borders`（双向写全），
   `Routes.ts` 会自动跟着变；**不要**从版图几何推导路，否则会画出「看得见却打不了」的假路。
2. **不能越过中间还有城的直达**：玩家看到 A 与 B 之间隔着 C，就不该能从 A 直接打 B，
   要拆成 A-C、C-B 两段。
3. **所有路常驻完整显示**，选中只加粗、不淡化其余。`tools/sim-routes.ts` 第 6b 段
   有静态守卫，别把 `dim` / `hasFocus` 淡化改回来。

`tools/sim-routes.ts` 还守住「每条 `isAdjacent` 都必须画成路、每条画出来的路都必须能打」，
且「橙红箭头数 == 玩家实际可攻方向数」「补给线数 == 可调兵方向数 / 2」。
改配色只需动 `MapRenderer.ts` 里的 `ROUTE_COLORS`。

## 八·八、开局身份：一眼找到自己执掌的势力

**现象**：开局只有一条约 2 秒就消失的「你执掌曹操」横幅，之后顶栏只剩
日期 / 金币 / 兵力 / 据点，地图上 18 个势力色块混在一起，玩家不知道
自己是哪个势力、哪片地盘是自己的。

**根因**：身份信息只存在于「一次性演出」里，没有任何常驻的可视锚点；
地图也没有区分「我方」的标记，势力色需要玩家自己拿横幅里的名字去对色块。

**修法**：三层信息互相印证，全部跟着 `state.playerFaction` 走。

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 常驻身份牌 | `GameController.buildHud()` 的 `FactionBadge`，顶栏下方左上角 | 26×26 势力主色色块（`Color.fromHEX(FACTION_MAP[fid].color)`）+「我方 曹操 · 3 城」；每次 `refreshHud()` 重画 |
| 地图标识 | `MapRenderer.draw()` | 己方版图 `shade(base, 1.45)`，其余势力仍是 `1.25`（只增强己方、绝不压暗别人）；`drawProvinces()` 给己方城池加常驻双层金环 |
| 一次性引导 | `showTutorial()` / `startNewGame()` / 读档 toast | 开局横幅「你执掌 X · N/35 城」、随后 toast 教认身份牌与金环；换剧本 / 换势力 / 重开 / 读档都重新点名 |

**点身份牌能定位**：`onLocateOwn()` 调 `pickFrontlineProvince()` 选己方前线城 →
`MapInput.focusOn()` 居中 → `reclampView()` 修正边缘（只平移不改缩放，
全图路网依旧一眼看全；想回全局视野点顶栏「全图」）。己方城池全没了会提示「已无我方城池」。

**为什么不用「淡化其余势力」**：路网阶段已经踩过一次 —— 把不相关的元素压暗，
玩家会直接读成「没画 / 不可见」。所以这里只把己方提亮一档，其余势力颜色原样保留；
金环只画在己方城池上，是城池标记，不是又添一层贯穿地图的装饰线。

**一个容易忽略的边界**：提亮是 `min(255, round(c * f))`。势力色本来就很亮时，
`1.45` 与 `1.25` 会双双 clamp 成纯白，「己方提亮」等于没画。当前 4 个可选势力
（曹操 `#3b6bd6` / 刘备 `#2fae5a` / 孙策 `#e0b12c` / 袁绍 `#8b5cf6`）
最大通道差分别是 21 / 34 / 34 / 28，都还看得出来；以后若把接近纯白的势力
（如公孙瓒 `#e8e3d3`）设为可选，`tools/sim-faction-identity.ts` 第 2 段会先失败，
那时需要改成描边或色温偏移，而不是继续调亮度倍率。

**接线铁律**（`sim-faction-identity.ts` 静态守卫）：

1. `refreshAll()` 必须同时 `draw(list, this.state.playerFaction)` 和 `refreshHud()`；
   两处 `mapRenderer.draw()` 调用都要带 `playerFaction`，否则换势力后金环还画在上一局的城上。
2. `MapRenderer.draw()` 里必须先 `this.playerFaction = playerFaction` 再 `renderRoutes()`，
   否则橙红箭头仍按上一局的「我方」判定方向。
3. `state.onTurnEnd = () => refreshAll()` 也负责刷新身份牌城数 —— 对手回合攻下我方城后，
   「N 城」必须跟着变。
4. 开局 / 新局 / 读档三条入口都要点名执掌势力，不能只剩常驻牌子。

## 八·九、城池发展度与内政

**要解决的问题**：以前每座城的产出只由人口决定，玩家除了「征兵 / 进攻」没有别的选择，
占了富城和穷城体感一样。现在发展度让「经营」成为一条可选路线。

### 一条因果链（先记住这个，其余都是它的展开）

```
发展度 dev ──devFactor()──> 金币 / 粮草 / 月募兵 / 屯田 四项月产出
                               │            │
                               │            └─ 粮草供给 → 月募兵（每回合自动到账、不用点）
                               └─ 金币供给 → 治理 / 筑城 / 征兵（内政四选一）
兵力 ──> 进攻 / 调兵（不占内政行动点）
```

- **金币 = 建设**，**粮草 = 养兵**。军队不直接吃金币，粮草也不直接买兵。
- **月募兵**是每回合经济结算里自动发生的常规兵役：不花金币，但吃粮草、受驻军上限约束。
  内政里的**征兵**是「花金币 + 人口额外买一批兵」，在结束回合的内政结算里到账
  （比月募兵早一步，赶得上 AI 行动，但赶不上本回合玩家自己的进攻）。
  两者是同一件事的两个速度，不是两套系统。
  面板上叫「月募兵」，避免和「自动内政」的「自动」撞词。

### 唯一的发展度倍率

| 产出 | 公式（`GameState`） | 作用 |
| --- | --- | --- |
| 金币月收 | `pop × 4 × 大城加成 × devFactor` | 征兵、治理、筑城 |
| 粮草月产 | `pop × 1.6 × devFactor` | 月募兵、筑城 |
| 月募兵 | `pop × 3.5 × devFactor`，每兵耗 `foodPerAutoTroop`（0.45）粮 | 每回合自动补，不用点 |
| 屯田产出 | `pop × 2.2 × devFactor` | 一次性补粮 |

`devFactor = 1 + dev/100 × devOutputFactor`（当前 `devOutputFactor = 1.0`）。
**四项产出共用这一个函数，没有第二套系数**：治理 +8 就是这座城所有月产出 +8%，
从 0 养到 100 就是全部翻倍。人口只决定规模，发展度只决定效率。

早先四项各写一套公式（金币 ×0.8、粮草 ×1.0、补兵 `dev/100×(1+pop/40)`、
屯田 `(1+dev/100)`），人口还在补兵里被乘了两遍，玩家根本判断不出治理值不值。
开局发展度 = `pop × 1.5 + (大城 ? 10 : 0)`，钳在 0~100；**旧存档缺 dev 时用同一公式回退**。

粮草单价 `foodPerAutoTroop = 0.45` 让收支基本持平：月产 `pop×1.6`、
募兵吃 `pop×1.575`（都乘 devFactor）。早先 0.25 只吃掉四成产粮，
玩到 200 回合粮草攒到 24 万，「屯田」和「缺粮就少募兵」全成了摆设。

### 一条铁律：执行时点只有一个

> **回合内只做选择，点「结束回合」才统一结算执行。**

以前点一次「筑城」会立刻加工事、扣钱粮，结束回合的自动方针又给其余城补一轮 ——
同一次点击跑了两批内政，玩家根本算不清这回合到底筑了几次城。现在：

```
玩家回合：点内政键 = 往 ProvinceState.pendingDomestic 登记（不扣资源、不改数值）
              · 再点同一道 = 取消，点另一道 = 改选
              · 进攻 / 调兵照常即时生效，与内政无关
结束回合：endTurn() → settleDomestic()  ← 全游戏唯一执行玩家内政的地方
              · 每座城用 effectiveOrder() 算出唯一指令，执行一次
              · 登记过的城优先按登记执行，其余城在「自动」开着时按方针补齐
              · 失败的城不会被自动方针拿去重试第二道
              · 结算完清空登记与 acted
```

`effectiveOrder()` 是「这座城这回合到底做哪一道」的唯一答案，面板高亮、按钮文案
和回合结算都问它，不各写一套分支。登记状态会写进存档，中途退出不会丢选择。

### 内政四令（每城每回合四选一，共用 `acted`）

| 指令 | 消耗 | 收益 | 定位 |
| --- | --- | --- | --- |
| 治理 | 240 金 | 发展度 +8 | 投资未来：之后所有月产出都更高 |
| 屯田 | 无 | 一次性粮草 | 补粮，让月募兵不因缺粮减员 |
| 筑城 | 180 金 + 60 粮 | 工事 +1（上限 9） | 守城，`fortPerPoint` 已接入战斗 |
| 征兵 | 金币 + 人口 | 结束回合时补兵 | 解决当下；一次只补 `recruitFillRatio`（60%）缺口，最多动 `recruitGoldShare`（25%）国库 |

**征兵为什么限额**：旧版把「全部金币 ÷ 单价」当征兵规模，点一下国库清零；
自动征兵时排序第一的城把钱全拿走，其余城全部提示「金币不足」。
现在多座城能分到预算，也给治理 / 筑城留了钱；想补满就下回合再征一次。

**军事行动不占这个行动点**：进攻、调兵照常，一回合可以既治理又出兵。
失败的内政不扣资源、也不吃行动点。攻占会打烂城池（`captureDevLoss = 0.25`），
抢来的城发展度掉四分之一，要重新经营。

### 内政自动化：一个「自动」开关 + 最后一道指令

城一多，逐城四选一就成了体力活。但**不要再摆第二套内政按钮** ——
两排一模一样的词并排，玩家分不清哪个是给当前城下令、哪个是设方针。

- 开关**关**：纯手动，每城自己选一道（默认关，没表态就不替玩家花钱）。
- 开关**开**：结束回合统一结算时，给「本回合没自己登记指令」的城执行
  **最后点过的那道指令**。想换就点另一个内政键 —— 点一下既给当前城登记，也把方针换掉。
- **方针变化必须看得见**：对应内政键亮底金边、面板常驻「自动：治理 · 点内政键换」，
  手动改方针时 toast 直接写「自动方针→征兵」。不会点了一下救急征兵、
  结果之后全境每回合都在征兵却毫不知情。
- **「选了」不等于「执行了」**：面板写「待执行：筑城（结束回合结算）」，
  内政 toast 写「已选筑城，结束回合执行」，结算后再报「内政 3 城（自动 2）」。
- 面板不用 `✓` 之类符号表意（系统字体缺字形会渲染成豆腐块）。

| 项 | 说明 |
| --- | --- |
| 生效时机 | 点「结束回合」后、**经济结算与 AI 行动之前**，在 `settleDomestic()` 里和手动登记一起结算；玩家回合内绝不执行 |
| 作用范围 | 只补「本回合没自己登记指令」的城；**选了就对所有这样的城执行**，不再替玩家判断需不需要 |
| 唯一指令 | `effectiveOrder()`：手动登记 > 自动方针 > 不选；每城只尝试一次，失败也不重试 |
| 排序 | 手动登记的先执行（玩家明确点过的优先花钱）；自动补齐的按指令类型排序 —— 治理按 dev 从低到高、屯田按 dev 从高到低、筑城**前线优先**再按工事低到高、征兵按兵力缺口比例从大到小 |
| 边界 | 只有「资源不够」才会跳过（`executeDomestic` 自己判断），不报错 |
| 反馈 | 回合结算 toast 写「内政 3 城（自动 2）」，战报留一条汇总，面板写「待执行：治理（结束回合结算）」 |
| 持久化 | 存档写 `autoDomestic` + `lastOrder` + 每城 `pending`；旧档缺 `pending` 回退「未选择」，`policy:'farm'` → 开自动+屯田，`policy:'manual'` → 关自动 |

**删掉的两处「自作主张」**：以前粮草高于 600 时整轮自动屯田直接跳过、
自动筑城只给前线城，玩家明明选了方针却看不见任何动静。现在排序可以优化
「先花在哪」，但不许静默剔除 —— 筑城改成前线优先、后方只是排在后面。

状态层只有两个字段，`domesticPolicy` 是它们的访问器，不再单独存第三份「方针」：

```ts
public autoDomestic = false;                // 开关
public lastOrder: DomesticOrder = 'govern'; // 自动重复哪一道

get domesticPolicy(): DomesticPolicy {
    return this.autoDomestic ? this.lastOrder : 'none';
}
```

### 回合顺序：内政 → 经济 → AI

```
玩家回合内登记（不执行）→ 结束回合统一结算内政 → 经济结算（收钱粮 / 人口增长 / 月募兵）→ AI 行动 → 进入下月
```

治理当月就兑现成月收，月募兵在双方出兵前到账，AI 用的是结算后的兵力。
旧顺序是「内政 → AI 攻城 → 结算」：治理花的是上月末余额，城被 AI 夺走后钱白花，
战报里的「月收」还变成了 AI 打完之后的**预测值**。现在 `TurnReport`
三个经济字段统一是**本月实收**，面板上的月收另按单城 `provinceIncome()` 实时算。
（原先给 AI 阶段用的 `totalIncome()` / `totalFoodIncome()` 随之成了没人调用的死代码，
已一并删除。）

### 公开的规则，不留暗改

- `aiSupplyFactor`（0.7，**难度设定**）：AI 月募兵效率是玩家的 70%。
  AI 不做治理 / 屯田 / 筑城（**会花钱急征**，见八·十一），人口不掉、驻军长期满编，
  这是明确写出来的难度让步，不是隐藏修补；改这个值后请重跑 `sim-ai.ts`
  与 `sim-game.ts` 看强度曲线。
- `Balance.ts` 里**每个字段都必须有实际引用**。以前躺着
  `turnLimit` / `recruitMin` / `armyMaxMp` 等 9 个从未接线的参数，
  看着像「游戏有回合上限、有军团机动力」，其实全是摆设，已删除。
  `tools/sim-development.ts` 末尾有守卫逐个检查，防止再留假参数。
- `sim-game.ts` 的长测（**固定种子 777**，最多 200 回合，分出胜负即停）：
  当前 **103 回合统一天下 35/35**、武将守恒 48/48。长测会**经营俘虏营**
  （好招的招、死忠的放归），招降 25 人次 / 放归 156 人次两条分支都被真跑到，
  结束时在营 4 人；方针以治理为主，屯田 / 筑城 / 征兵的自动化分支由
  `sim-development.ts` 第 9 段逐条覆盖。
  这个模拟玩家**不会主动集结、只在缺兵时征兵**，所以比 `sim-pace.ts` 慢得多
  （103 vs 18~21 回合），国库也结余到 4.7 万 —— 两条曲线正好框住「会用机制」
  和「只点结束回合」两类玩家，也说明后期金币出口仍然偏少（见「十、已知限制」）。
  长测以前吃 `Math.random`，同一份代码每次跑出的回合数与俘虏数能差几十，
  数字根本没法写进文档；现在用 `setRandom()` 钉死随机源（与 `sim-pace.ts` /
  `sim-ai.ts` 同一个 LCG），`SG_SEED` / `SG_TURNS` 可临时换种子扫描。
  扫描 8 个固定种子：4 个能在 200 回合内统一，另外 4 个被动玩家停在 11~32 城 ——
  AI 变强后，**残局硬城必须靠超编集结才推得平**，这是机制门槛不是死锁
  （会算胜率并集结的玩家由 `sim-pace.ts` 保证 6/6 通关）。

**顺手修掉的老 bug**：`recruit()` 原来按「当前人口的上限」征满，扣完人口后新上限下降、
多出来的兵被截断 —— 花了钱、掉了人口，兵却凭空消失（实测征 1550 只到手 935）。
现在迭代收敛到「扣完人口后仍不超新上限」的量，`capAt(st, pop)` 按未来人口试算。

**UI**：顶栏常驻「粮草」；面板正文 6 行（兵力 / 人口工事 / 发展度 / 月收月粮 / 月募兵 / 守将）；
按钮两行 —— 上排「自动」开关 + 内政四键、下排「进攻 / 调兵 / 取消」；
这座城将要执行的那道指令在对应内政键上亮金边，面板写「待执行：X（结束回合结算）」。
内政键不再变暗：登记只是选择，随时能改选或再点一次取消（`setDomesticDim()` 已删）。
两栏对齐按像素估宽补空格（原来按「中文算 2 宽」补，中英混排时右栏每行起点都不一样）。

## 八·十、君主、武将 / 文官与俘虏营

> 需求原话：「武将和文官是有忠诚度的，可以抓到对方将领进行招降，
> 如果不愿投降可以放走降低他的忠诚度，方便下次进行招降」。

### 一条因果链（其余都是它的展开）

```
攻破敌城 → 每名守将按 50% 概率被生擒 → 俘虏营二选一
   ├─ 招降：按 (100 − 忠诚)/100 + 我方君威 掷骰
   │    成功 → 改旗易帜、以 60 忠诚进驻我方一城
   │    失败 → 忠诚 +10（越劝越硬，人还关着）
   └─ 放归：回原势力人口最多的城，忠诚 −25（旧主猜忌「何以独归」）
              → 下次再被俘，成功率正好高出 25 个百分点

势力最后一城被攻破 → 该国所有将领忠诚 −30（国破人心散）
   └─ 君主从「在位」变「亡国」：不再是君主，按普通将领招降
```

关键是那句反直觉但自洽的设计：**放走不是放过，是给下次铺路**。反复劝降只会让
他更坚定，所以高忠诚名将的正确打法是「先放回去，等下回再抓」。

### 数据与唯一的成功率公式

- 48 名将领在 `data/Generals.ts` 里逐一标注 `role`（武将 / 文官）、
  `ruler?`（每势力最多一位君主）、开局 `loyalty`。史实上死忠的给高分
  （关羽 / 典韦 100~98），反复易主者给低分（蔡瑁 55、张郃 65）。
- `RULER_OF` 从将领表**自动派生**，不在 `Factions.ts` 里再写一份，避免两个真相源。
- 运行时以 `GeneralState.faction` 为「现在是谁的人」；`def.faction` 只用于开局布阵。
  招降成功会改 `faction`，旧档缺字段时回退到 `def.faction`。
- 身份**不影响成功率**：文官和武将用同一条公式，不给文官开隐藏后门。
  `role` 只是让玩家看清抓到的是谁。

```ts
persuadeChance(g) = isReigning(g) ? 0 : (100 - g.loyalty) / 100 + persuadeBonus()
```

UI 把 `Math.round(chance * 100)` 原样显示出来，不另写一套判定；
**在位**君主显示「不可招降」、招降键画暗，点了也会给出明确原因（「先夺其城池」）。
亡国君主照常显示成功率 —— 这就是「失去所有土地后可以招募」在界面上的样子。

| 参数（`Balance.ts`） | 值 | 含义 |
| --- | --- | --- |
| `captureGeneralChance` | 0.5 | 攻破城池时每名守将被生擒的概率 |
| `releaseLoyaltyDrop` | 25 | 放归后忠诚下降 |
| `persuadeFailLoyaltyGain` | 10 | 招降失败后忠诚上升 |
| `recruitLoyalty` | 60 | 归降后对新主的初始忠诚 |
| `fallenLoyaltyDrop` | 30 | 亡国时该国所有将领忠诚下降（君主 100 → 70，才招得动） |
| `loyaltyMin` / `loyaltyMax` | 10 / 100 | 忠诚上下限，下限保证不会白送 |

忠诚下限 10 是刻意的：反复「抓了放、放了抓」最多把成功率推到 90%，
永远留一点气节，不会出现必然归降。

### 君主：在位不可招，亡国可以招

> 需求原话：「君主失去所有土地以后可以招募的」。

规则不是「君主永远不可招降」，而是「**在位**君主不可招降」：

```ts
isReigning(g) = g.def.ruler
             && RULER_OF[g.faction] === g.def.id   // 这个势力的君主就是他
             && provincesOf(g.faction).length > 0  // 而且他还有城
```

- **在位**：成功率恒为 0，俘虏营里招降键画暗，点了给「先夺其城池」。
- **亡国**（最后一城被攻破）：`onFactionFallen()` 让该国**所有**将领忠诚 −30。
  君主从 100 掉到 70 → 成功率 30%（若我方有曹操再加 15%）。
- 亡国君主**放归也降忠诚**了（他不再是「主」，回去也没江山可坐），
  再被抓一次掉到 45 → 55%，「灭国 → 生擒 → 放归 → 再擒 → 招降」整条链闭合。
- **招降成功**：`faction` 改成我方，`RULER_OF` 对不上他，`isReigning` 自动变 false。
  他不再是君主，而是**带加成的客将** —— 不需要额外的「降级」字段，
  身份是由 `faction` + `RULER_OF` + 城池归属三件事共同决定的。

为什么一定要「亡国降忠诚」：君主开局忠诚 100，成功率恒 0。
不降忠诚，这条规则写了也等于没写。`fallenLoyaltyDrop` 就是让规则真正生效的那一环，
`sim-prison.ts` 第 8 段用真实攻城把这条链跑了一遍（公孙度 100 → 70 → 招降 45% → 归降）。

### 君主加成：按历史定位，一人一项

> 需求原话：「君主武将可以根据历史定位给出不同的加成」。

16 位君主在 `Generals.ts` 里各带一项 `bonus`（`RulerBonus`），全部是公开百分比：

| 君主 | 称号 | 加成 | 作用范围 |
| --- | --- | --- | --- |
| 曹操 | 唯才是举 | 招降 +15% | 全局（已在我方阵营时） |
| 孔融 | 座上客满 | 招降 +10% | 全局 |
| 吕布 | 飞将 | 进攻 +25% | 驻守城发起进攻 |
| 孙策 | 小霸王 | 进攻 +20% | 同上 |
| 马腾 | 西凉铁骑 | 进攻 +20% | 同上 |
| 公孙瓒 / 李傕 / 张绣 | 白马义从 / 西凉悍卒 / 北地枪王 | 进攻 +15% | 同上 |
| 刘璋 | 天府之国 | 粮草 +25% | 驻守城月产出 |
| 刘备 | 仁德 | 粮草 +20% | 同上 |
| 张鲁 | 五斗米道 | 粮草 +20% | 同上 |
| 袁绍 | 四世三公 | 金币 +20% | 驻守城月收入 |
| 刘表 | 荆襄富庶 | 金币 +20% | 同上 |
| 袁术 / 士燮 | 淮南殷富 / 交州偏安 | 金币 +15% | 同上 |
| 公孙度 | 辽东自守 | 防御 +20% | 驻守城被进攻 |

两条硬规则：

1. **只作用于君主驻守的那座城**（`atk` / `def` / `gold` / `food`）。
   把君主调到哪里、哪座城才吃到加成 —— 这是一步可以操作的决策，
   不是「招到就永久全局 +20%」的被动数值。城池面板右栏那行
   「君威 孙策·小霸王 攻+20%」说的就是这件事；君主不在本城时改报
   「君主 曹操（在 洛阳）」，玩家才知道该往哪调。
2. **同城多位君主取最高，不叠加**（`rulerBonusAt()` / `persuadeBonus()`）。
   否则把几个招来的旧主塞进一城就能堆出离谱战力，玩家会立刻发现
   「堆君主」是唯一最优解。`sim-prison.ts` 有断言守着。

`persuade` 是唯一的全局项：它作用在俘虏营里，跟君主站哪座城无关。

加成接在既有的三处公式上，没有第四条链：

| 加成 | 接线点 |
| --- | --- |
| `atk` / `def` | `CombatSide.mul` → `resolveBattle()` 的 `atkMul` / `defMul` |
| `gold` | `provinceIncome()` 末尾乘 `(1 + rulerBonusAt(st, 'gold'))` |
| `food` | `foodIncome()` 末尾乘 `(1 + rulerBonusAt(st, 'food'))` |
| `persuade` | `persuadeChance()` 里加 `persuadeBonus()` |

`mul` 与 `atk`/`def` 的等级和分开是刻意的：等级和是**加法**（多带一个将多一份），
君主加成是**乘法**（整体战力抬一个百分比）。折进等级和里会变成
「将领越多、加成越被摊薄」，与「君威」的语义相反。

一人只给一项加成也是刻意的：城池面板右栏只有一行位置，多写一条要么截断、
要么藏规则。`BONUS_KIND` 是唯一的显示顺序表，以后给某位君主加第二项，
面板会自动多显示一项，不用改 UI。

### 俘虏只有一处去处

`GeneralState.captiveOf` 是唯一真相源：`''` = 自由身（在某座城的 `generals` 里）；
否则被该势力关押。俘虏**不在任何城池的 `generals` 数组里**，所以守恒口径改成
「在城 + 在营 = 48」——`logic-test.ts` / `sim-game.ts` / `sim-save.ts` /
`sim-showcase.ts` 四处断言都跟着改了，少算一边就会误报「武将凭空消失」。
`deserialize()` 还有兜底过滤：脏存档里若有人同时挂在城上又标着俘虏，
读档时把他从城上摘掉。

放归去处按优先级：**原势力人口最多的城 → 中立城 → 非玩家城**。
原势力已亡时不能让人凭空消失，流亡到中立 / 他势力城，
玩家日后打下那座城还能再抓他一次，「放归 → 再俘 → 更易招」的链条不断。
归降安置则挑我方驻将最少、其次人口最多的城。

### 公开的不对称：AI 不关押俘虏

`attack()` 里 `mayCapture = captor === playerFaction`：**只有玩家攻占会生擒**。
AI 没有招降界面，把将领关在玩家看不见的地方，只会让 48 人从地图上凭空消失，
还悄悄削弱敌方战力。突围的守将照旧撤回原势力最近的己方据点；
若原势力已亡且突围成功，则就地归顺并明确改掉 `faction`。
这条不对称写在源码注释和这里，`sim-prison.ts` 第 3 段有运行时断言。

生擒和招降都走 `Combat.random()`（同一个可注入随机源），
测试只要 `setRandom()` 一次就能把「这次到底抓没抓到 / 降没降」钉死；
没有各自为政的 `Math.random()`。

  自然沉底，亡国君主掉到 70 就会浮上来。

## 八·十一、AI：会用国力、会集结、会协同

旧 AI 只有一条规则「单城裸兵力比 > 1.15 就撞」。用探针量化出来的症状：

| 症状 | 根因 |
| --- | --- |
| 后期整局零出兵 | 玩家一超编，ratio 掉到 0.8，1.15 硬门槛永远够不着；AI 既不集结也不换目标 |
| 名将三十余员、国库 1.6 万金，却「国力那么强打不动」 | 决策只看 `troops`，将领等级 / 君威 / 工事全不进公式；金币一分钱不花 |
| 反复送人头 | 1.15 在三轮消耗战里根本打不崩守军防线，AI 却照撞不误 |
| 各打各的、互相抢同一座城 | 每城独立决策，没有目标优先级，也没有波次协同 |

现在的决策链（`GameState.aiFactionAct()`，每势力每回合一次）：

1. **侦察**：列出所有可攻敌城，按 `胜算 × 价值` 排序（大城 ×1.25、玩家城 ×1.1）。
2. **统一口径**：`aiPowerRatio()` 用与 `previewAttack()` / `resolveBattle()` 相同的
   「兵力 × 将领等级 × 君威 ÷ 工事」算战力比，再过 `winRateOf()` 得胜率。
   玩家面板看到的「胜算偏险」和 AI 眼里的是同一条曲线，不再各算一套。
3. **集结**：算「打崩守军还差多少兵」（`aiBreakthroughRatio`），沿路网 BFS 把
   后方余兵一跳一跳接力到主攻城；每城保留 40% 守备，超编走与玩家相同的
   `moveTroops()`。目标是我方城时，战报会写「XX 自后方集结 N 兵于 YY，图谋 ZZ」，
   玩家能看见对手在谋什么。
4. **调将**：把后方闲置名将按攻击等级择优调到主攻城，补到 `generalsPerCity`
   参战上限。将领只换城、不增不减，守恒不变。
5. **花钱**：仍不够就动用国库急征（`aiRecruitBudget`），补给同一方向的各路兵源 ——
   只补主攻城的话，它常被集结顶到超编上限，`recruit()` 一间也征不到，
   国库就越堆越高。补第二路兵源既让钱有出口，也让夹击真的有兵。
6. **多路协同**：每一波重新评估胜算，第一波削守军、第二波趁虚而入；
   低于 `aiMinWinRate` 就收兵，不送人头。主攻之外尚有余力才顺手捡软柿子。

难度全部由 `Balance` 里公开的 `ai*` 参数控制（见「五、数值与平衡」），没有隐藏加成：
AI 的调兵、征兵、超编损耗、月募兵折扣与玩家同一套规则。
`tools/sim-ai.ts` 用运行时钩子精确记录集结 / 调将 / 征兵 / 协同四个阶段的真实动作，
并守住「不留假参数、难度设定全部写进 README」。

**难度校准**：探针试过「每势力 5 路」的一档，玩家开局被打回 6 座城、一局拖到 50 回合；
收敛到 3 路后，`sim-pace.ts` 6/6 通关、18~21 回合、僵持 0%。
`sim-ai.ts` 第 5 段用固定种子钉住「AI 全局出兵 130 次（旧版 53 次且后期停摆）、
玩家 20 城之后仍出兵 26 次（旧版为 0）」，同时这一局玩家仍能 18 回合统一天下。
AI 活跃反而让局面流动、双方守军都有消耗，比「叠满兵互瞪」更容易打完。

## 八·十二、二次试玩：不动数值，改「看得懂」

AI 增强后又按真人玩法跑了一轮固定种子试玩（会看 `previewAttack().winRate`、
会调兵集结、会经营内政、会处置俘虏，但不作弊）。6 局都能通关，可拉锯感很重：

| 现象 | 探针实测 |
| --- | --- |
| 开局被打懵 | 3 座城常在 T2~T3 掉到 2 座，全局丢城 24~71 次、被攻城 26~78 次 |
| 白打循环 | 攻占 73~103 次里 52%~66% 后来又丢，其中「下一回合就丢」21~48 次 |
| 新城太薄 | 攻占后平均驻军 278~317，而驻军上限 1423~1502，只有约 20% |
| 战报过载 | 每回合 7.8~8.9 条、峰值 18~19 条，而窗口只显示最后 4 行；玩家相关要闻 42%~59% 被挤出 |

**先试过直接改数值，全部被数据否掉了**：

- 提高 `captureGarrisonRatio`（0.55→0.95）：30.3 回合拖到 76.0，白打率 58%→82%。
  AI 夺回玩家城时同样留更多兵，战线越拉越长。
- 补给优先最缺兵 / 给新城整编防御加成（+60%、+120%）：全部更慢、更磨，
  有一档 6 局只通关 5 局。
- 开局给玩家 1~3 回合缓冲（`aiOpeningGraceTurns`）：AI 无人打扰地互相吞并，
  养出巨型对手，普通玩家反而从 30.3 拖到 54.5 回合，被动玩家被压死。
- 调低 `aiPlayerTargetBias`：只让「普通玩家」舒服，熟练 / 被动两类都变差。
  三类玩家一起看，现有 `1.1` 最稳（熟练 6/6 · 19 回合，普通 6/6 · 30 回合，
  被动 6/6 · 38 回合）。

结论是**一个数值参数都不改，撤销所有临时缓冲**，改为修信息可见性 —— 玩家不是打不动，
是不知道该往哪打、该往哪防。两处改动：

1. **战报要闻置顶**。`pushLog(msg, priority)` 给每条战报分级：
   `2` = 玩家丢城 / 攻占 / 失利 / 生擒 / 招降 / AI 图谋玩家城，
   `1` = 玩家内政与结算，`0` = 其他势力动态。
   `recentLogs(3, 5)` 把最近 3 条要闻按时间正序钉在窗口顶部，普通日志只补剩下空位，
   同一条不会取两次；`logs` 与重要度数组在 200 条上限处同步裁剪。
   面板战报框从 `340×96` 加到 `340×140`（5 行），加了半透明暗底，改为顶部对齐 + `CLAMP` 裁剪：
   溢出的只会是末尾普通日志，不会再自动增高盖到地图城池标签上，文字也不会和底图糊在一起。
   要闻用 `! ` 前缀标出
   （不用勾选符号，系统字体缺字形会渲染成豆腐块）。
2. **敌情预警 `GameState.threats`**。AI 自后方集结、目标是我方城时，除了钉成要闻，
   还把「谁、多少兵、在哪集结」记到 `threats[城池 id]`。它留到玩家下一回合：
   战报框下方的常驻敌情条、被选中城的面板标题、底部提示条都会写明
   「敌军图谋此城 · 可调兵回防」。城若当回合已失守，`liveThreats()` 自动过滤掉过期预警；
   每次 AI 阶段开头刷新，`reset()` / `deserialize()` 清空，不进存档。
   这样「AI 有意图」才真正变成「玩家有对策」。

`tools/sim-report.ts` 用运行时钩子验证重要度真的接在每个战报源上，并复现
「灌入 12 条背景战报后要闻仍置顶」「预警留到玩家回合」「城易主后预警失效」。
「白打循环」本身作为机制取舍保留：见「十、已知限制」。

## 八·十三、上线增长设计：先补「首次体验 → 目标感 → 炫耀 → 回来再玩」

前面十一节都在解决「好不好玩」，这一节换个问题：**上线之后凭什么有人玩下去**。
玩法已经能跑通（6/6 通关、18~21 回合），但产品闭环是断的：

- 新玩家进游戏只有三条定时 toast，看完还是不知道「我现在该干什么」；
- 一局要 18~40 回合，中途没有任何「我快赢了」的阶段性反馈；
- 打赢只有一行「四海归一」，没有可比较的成绩，也没有理由发给朋友；
- 关掉游戏后什么都不剩，第二次打开和第一次一模一样。

所以这次不继续堆玩法，而是补一条**留存闭环**，并按优先级拆成五段：

| 阶段 | 要解决的问题 | 关键动作 | 状态 |
| --- | --- | --- | --- |
| P0 能上架 | 审核与崩溃 | 真实 AppID、隐私协议、错误上报、构建产物校验 | 部分就绪（构建配置 / 方向 / 包体校验插件已有，AppID 仍是占位值） |
| P1 前 3 分钟留得住 | 不知道怎么玩、没有目标 | 任务式引导 + 阶段目标 + 本局战绩 + 战绩结算 + 分享理由 | **本次完成** |
| P2 明天还回来 | 一局打完就没了 | 成就图鉴、每日挑战、难度阶梯、剧本解锁 | 待做 |
| P3 带来新的人 | 没有传播理由 | 战绩卡图片、好友挑战、微信排行榜 | 文案分享已打底，图片 / 榜单待做 |
| P4 可持续 | 没有长期内容 | 激励视频只换便利不卖数值、皮肤、赛季剧本 | 待做 |

### 四条设计铁律

1. **一个 `Balance.ts` 参数都不改。** 八·十二 已经用数据证明，改留兵比例 / 保护期 /
   玩家权重都会把 18~21 回合的节奏推向某一类玩家更难受。P1 只给信息，不给数值。
2. **不发金币 / 兵 / 粮。** 任何「引导奖励」「成就奖励」都会直接抬高开局资源，
   等于偷偷改平衡。这里所有正反馈都是文案与记录。
3. **局外档案走独立 key。** `sanguowar_save_v1` 会在新开一局时被清掉，
   累计成绩必须存在 `sanguowar_profile_v1`；`SAVE_VERSION` 仍保持 1，
   本局战绩 `stats` 只是可选字段，旧档缺失时按当前局面重建。
4. **引导不弹遮罩、不拦截点击。** 现有 `sim-interaction.ts` / `sim-play.ts`
   依赖真实点击链路，加一层模态会让整组测试失效，也会让老玩家烦躁。

### P1 具体做了什么

1. **任务式引导**（`core/Profile.ts` 的 `TUTORIAL_STEPS`）。
   左上角常驻一条目标条，五步各接一根真实操作线：
   点城 → 下一道内政 → 结束回合 → 自己攻占一座城 → 看到战报里的 `!` 要闻。
   只有真的做了才推进，重复点 / 跳着做都不会把进度推乱；
   原来的三条定时 toast 保留为补充说明（`sim-faction-identity.ts` 仍在守卫它们的文案）。
2. **阶段目标**（`objectivesOf()` / `objectiveLevel()`）。
   按「开局城数 + 总城数」推算出 `立足 / 破局 / 问鼎` 三个门槛，
   35 城剧本约为 5 / 13 / 35 城。目标条常驻显示「当前 / 下一目标」，
   达成时 toast 一次；丢城回退不重复播报，重新达成才再给一次。
3. **本局战绩 + 局外档案**。
   `GameState.stats` 只记事实：攻占、丢城、招降、放归、最大版图；
   `PlayerProfile` 跨对局记场次、统一数、最快回合、成就、最近战绩。
   结算面板可能被反复打开（读档、剧本弹窗返回、继续看看），
   用 `resultRecorded` 保证档案只记一次。
4. **战绩结算页**。从 4 行文字扩成「剧本 / 用时 / 评价 / 据点 / 攻占 / 丢城 /
   收降 / 放归 / 累计成绩 / 分享语」，评价只按回合数分档
   （`S ≤ 20`、`A ≤ 28`、`B ≤ 40`、其余 `C`），不看金币存量，避免诱导囤钱不打。
   四个按钮改 2×2，新增「分享战绩」不挤掉原来的「再开一局 / 换个剧本 / 继续看看」。
5. **分享钩子**。`WeChatAdapter.setShareText()` 把分享文案从静态标语改成模块变量，
   已注册的 `onShareAppMessage` 每次都读最新值，所以结算后右上角「···」转发
   直接带「我用 19 回合统一天下……你能几回合？」。
   H5 / 编辑器没有剪贴板时降级为可读提示，不静默失败。

`tools/sim-onboarding.ts` 把这些钉成断言：引导五根线、目标推算与回退、
档案脏数据兜底、战绩五项计数、旧档缺 `stats` 回退、结算只记一次、
分享回调读最新值、README 公开，以及「档案层不 import `Balance`」这条铁律。

## 十、已知限制

- 城池固定为 35 座，尚无地图编辑器；新增城池需在 `Provinces.ts` 里补
  经纬度、`borders`、`region`，并把双向相邻关系都写全（测试会校验对称性）。
- 路网是城池之间的直线，当前 58 条里已无「从第三座城身上穿过」的越城直达
  （曾有 2 条，已从 `borders` 双向删除）；靠两端的「路口」圆点区分归属，未做自动弯折避让。
- 地形装饰（山脉 / 河流 / 州界 / 版图边界）数据保留在 `MapRenderer.ts` 顶部但暂不绘制，
  底图目前只有路网一层线；如需恢复地形层次，可给这些数据加一个开关重新调用。
- 己方版图靠「提亮一档」区分，只适用于当前这批不接近纯白的势力色；
  若把很亮的势力设为可选，需改用描边/色温方案（详见八·八，`sim-faction-identity.ts` 会拦截）。
- 所有剧本共用同一套城池与武将表，剧本只改归属 / 年月 / 兵力 / 可选势力；
  要做完全不同地图的剧本，需扩展 `Provinces.ts` 与 `Geo.ts`。
- 地理轮廓是「可辨识」级简化（约 49 个海岸控制点），不是精确 GIS 数据。
- 发展度上限 100，目前只有「治理」一条提升途径（+8/次），没有下降途径。
- **后期金币仍会偏结余**：粮草已有驻军粮饷出口（`foodPerTroopUpkeep`），太平年月不再
  无限滚粮；金币的持续出口仍只有治理 / 筑城 / 征兵。会主动集结 + 征兵的玩家
  （`sim-pace.ts`）通关时剩 4 千金上下（峰值 4213），但**只开自动治理、发展度养满后
  不再花钱**的玩家（`sim-game.ts`，固定种子 777）103 回合仍结余约 4.7 万，
  换成种子 999 会堆到 19 万 —— 自动方针不会因为「治理已经做不动了」就擅自改换指令
  （见八·九「不许静默替玩家判断」），钱就留在库里。AI 变强后前线会持续吃征兵，
  所以这个结余比旧版小得多，但出口仍然只有这几条。
  刻意保留这个取舍：要彻底闭环可加「按驻军收金币军饷」，或让玩家把方针切到征兵，
  但那会再叠一条收支链。早先的死锁（最后一座中立城堆 8 将、守军被月募兵养满，
  200 回合卡在 34/35）已修：中立城不自动募兵、流亡将分散到驻将最少的中立城、
  守将参战封顶 5 名。
- **完全不集结的被动玩家会在残局停住**：AI 增强后会持续削前线、把剩余硬城养起来，
  `sim-game.ts` 换种子扫描时 8 个里有 4 个 200 回合内只停在 11~32 城，个别给到 400 回合
  也没统一。残局硬城必须靠「调兵填满 + 超编集结」凑出局部优势（见五、数值与平衡），
  这是游戏刻意要求的决策，不是死锁：会看胜算并集结的玩家由 `sim-pace.ts`
  保证 6/6 在 18~21 回合通关。若想让纯挂机也能收官，得放松 `aiBreakthroughRatio`
  或给自动方针加「转征兵」，那会明显削弱 AI 的压迫感。
- **刚打下的城容易下一回合又被夺回（「白打循环」）**：新城只留攻方剩余兵力，
  试玩里平均只有驻军上限的约 20%，而 AI 会主动集结反扑。二次试玩扫描过提高留兵比例、
  补给优先最缺兵、给新城整编防御、开局缓冲、调低 `aiPlayerTargetBias` 五种改法，
  全部让局面更拉锯或让某一类玩家更难打完（数据见八·十二），所以刻意不改数值。
  对策是**主动调兵回防**：敌情预警条会提前一回合点名被图谋的城，
  超编集结（`overCapFactor`）也能把兵堆到前线。想要「打下即稳」的轻松节奏，
  得单独加一套占领保护期，那会明显削弱 AI 的压迫感。
- 内政自动化默认关，所以开局要么自己逐城选、要么先打开面板上的「自动」开关；
  这是刻意的：没表态就不该替玩家花钱。开局引导会说明「内政键只做选择，结束回合才统一执行」。
- 因为内政统一在结束回合结算，本回合才选的「征兵」**赶不上本回合玩家的进攻**
  （但赶得上同回合的 AI 行动）。想当回合立刻出兵，只能靠调兵或上月结余的驻军。
  这是「只留一个执行时点」换来的取舍，刻意不再给征兵开一个即时后门。
- 月募兵按 `provinces` 的插入顺序消耗共享粮草，粮草不够时先遍历到的城先补；
  城多的势力可能觉得「补得不均匀」，需要按发展度加权分配时再改 `runEconomy()`。
- **俘虏营不会自动放人**：抓到的人一直关到玩家去处置，没有关押上限、不消耗粮草、
  也不会随时间自己跑掉。完全不处置的对照长测里曾积压 36 人 / 共 48 人，
  敌方城池守将变少、战斗变轻松、占地虚高。现在 `sim-game.ts` 会模拟玩家经营俘虏营
  （好招的招、死忠的放归），103 回合统一天下，结束时在营 4 人（都是终局前抓到的）。
  这是刻意不加的又一层机制 —— 处置俘虏是玩家的经营责任，顶栏按钮会一直亮着提醒。
  要闭环可加「关押耗粮」或「关满 N 回合自动流放」，但那会再叠一条收支链。
- **AI 不生擒**（详见八·十）：玩家单方面能把敌将收进营里，AI 攻下玩家的城时
  守将只会突围或就地归顺。这是为了让 48 名将领始终留在地图上可见，
  代价是双方规则不完全对称。
- **在位君主仍然收不了**：只要他还有一座城，成功率恒为 0、放归也不降忠诚。
  想收他必须先灭国，靠 `fallenLoyaltyDrop` 把忠诚打下来才有的谈。
  这是刻意的：打下两座城就能招，那「君主」这个身份就没有分量了。
- **招来的旧主不占君主位**：归降后他只是带加成的客将，`rulerOf(我方)`
  仍是我方君主，不会出现「一朝两主」。他的加成照样生效，
  所以「灭国 → 收其主」是一条有回报的长期路线，而不是纯收集。
- 归降将领一律以 `recruitLoyalty`（60）重新起步，没有按原忠诚 / 身份做差异化；
  也没有「忠诚过低会叛逃」这类反向机制。
- **P1 只做文案分享，没有战绩卡图片**：微信转发带的是文字标题
  （`onShareAppMessage` 的 `title`），没有生成 5:4 的战绩卡，也没有好友挑战 /
  排行榜。文案分享已经能跑通，但裂变效率主要取决于图片与榜单，属于 P3（见八·十三）。
- **局外档案没有版本迁移**：`sanguowar_profile_v1` 的字段全部可选 + 夹取，
  脏数据不会让玩家进不了游戏；但真的改结构时要换 key 或写迁移，
  当前不保证「旧成就自动折算」。
- 音效是程序化合成的占位音，音色偏电子感；正式上线建议替换为录制素材。
- 未做本地化；文本为简体中文硬编码。
- 战斗无地形修正（河流/山地），仅工事影响防御。
- 存档只有一个槽位，覆盖式保存；多存档位需扩展 `GameState.serialize` 的存储键。
- 构建配置里的 `appid` 是占位值，**上线前必须替换**。
- `core/Hex.ts` 是旧网格地图的遗留文件，已无引用；删除受当前环境权限限制，
  可在资源管理器里直接删除。
